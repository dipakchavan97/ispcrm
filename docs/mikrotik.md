# MikroTik RouterOS PPPoE & RADIUS Integration Guide

## 1. Overview

This document provides exact, production-grade RouterOS (v6 & v7) terminal commands to integrate a MikroTik Cloud Core Router (CCR) or x86 BNG as a PPPoE Network Access Server (NAS) communicating with the FreeRADIUS and ISPCRM platform.

---

## 2. Step-by-Step MikroTik Configuration

### 2.1 IP Pool Setup for PPPoE Subscribers
Create a subscriber IP address pool if not using static IP attributes from RADIUS:

```routeros
/ip pool
add name=pool-subscribers ranges=10.100.0.2-10.100.15.254
```

### 2.2 PPP Profile Definition
Define the default profile. Enable RADIUS accounting and configure DNS servers:

```routeros
/ppp profile
add change-tcp-mss=yes \
    dns-server=1.1.1.1,8.8.8.8 \
    local-address=10.100.0.1 \
    name=profile-ispcrm \
    only-one=yes \
    remote-address=pool-subscribers \
    use-compression=no \
    use-encryption=no \
    use-mpls=no
```

### 2.3 PPPoE Server Setup
Bind the PPPoE server to the subscriber aggregation interface (or VLAN):

```routeros
/interface pppoe-server server
add authentication=pap,chap,mschap2 \
    default-profile=profile-ispcrm \
    disabled=no \
    interface=ether2-subscribers \
    keepalive-timeout=30 \
    max-mru=1480 \
    max-mtu=1480 \
    one-session-per-host=yes \
    service-name=isp-broadband
```

### 2.4 RADIUS Client Configuration
Add the central FreeRADIUS server for PPP authentication and accounting:

```routeros
/radius
add address=192.168.1.100 \
    service=ppp \
    secret="SharedSecret123" \
    authentication-port=1812 \
    accounting-port=1813 \
    timeout=3000ms \
    comment="ISPCRM FreeRADIUS Server"

/radius incoming
set accept=yes port=3799
```
> [!IMPORTANT]
> `/radius incoming set accept=yes port=3799` is mandatory. This opens the RFC 3576 / RFC 5176 Change of Authorization (CoA) and Packet of Disconnect (PoD) listener, allowing the CRM to terminate or throttle active sessions in real time.

### 2.5 Periodic Accounting Interim Updates
Ensure MikroTik sends interim usage telemetry to FreeRADIUS every 5 minutes:

```routeros
/ppp aaa
set accounting=yes \
    interim-update=5m \
    use-radius=yes
```

## 3. Dynamic Bandwidth Control (Simple Queues)

When FreeRADIUS returns the attribute `Mikrotik-Rate-Limit = "20M/100M"`, RouterOS automatically creates a dynamic simple queue for that PPPoE interface:

```routeros
# Automatically generated by RouterOS upon user authentication:
/queue simple
add dynamic=yes \
    max-limit=20M/100M \
    name="<pppoe-user_rajesh>" \
    target=<pppoe-user_rajesh>
```

When the subscriber disconnects, RouterOS automatically cleans up the queue. No manual API queue management is needed, ensuring zero resource leaks on the router.

## 4. Subscriber Suspension Strategies

### Strategy A: Immediate Disconnect (Default & Recommended)
1. Customer subscription expires or bill is unpaid.
2. The CRM marks customer as `SUSPENDED` and changes `radcheck` password/attribute to reject.
3. The BullMQ worker sends a UDP Disconnect-Request to port `3799` of the MikroTik NAS.
4. MikroTik terminates the PPPoE session instantly.
5. Customer ONT/router dials PPPoE again -> RADIUS responds `Access-Reject` -> Connection halted.

### Strategy B: Walled-Garden / Captive Portal (Optional Extension)
1. When suspended, FreeRADIUS returns `Mikrotik-Rate-Limit = "64k/128k"` and `Mikrotik-Group = "suspended"`.
2. RouterOS assigns the subscriber IP to a firewall address-list `suspended_users`.
3. Firewall NAT redirects HTTP traffic (port 80) to the ISP payment portal (`http://pay.myisp.in`).

## 5. Firewall Rules for RADIUS & CoA

Ensure the MikroTik firewall permits incoming traffic from the FreeRADIUS server:

```routeros
/ip firewall filter
add action=accept chain=input comment="Accept CoA/PoD from ISPCRM" \
    dst-port=3799 protocol=udp src-address=192.168.1.100
```

## 6. Diagnostic & Troubleshooting Commands

```routeros
# View active PPPoE sessions
/interface pppoe-server print

# View live simple queues created by RADIUS
/queue simple print where dynamic=yes

# Check RADIUS communication status and error counters
/radius monitor [find comment="ISPCRM FreeRADIUS Server"]

# View incoming CoA/PoD requests processed
/radius incoming monitor
```
